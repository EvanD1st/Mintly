# OpenSea eligibility connection and explicit mint phases

Imported signing wallets can authorize read-only OpenSea sign-in inside Mintly. Wallet details has **OpenSea eligibility access**. The user explicitly permits the canonical OpenSea sign-in message, its Terms of Service and Privacy Policy, and credential renewal within the finite permission window. Address-only wallets cannot authenticate with Mintly because Mintly has no signing key for them. Public plans remain usable without this connection.

The isolated custody signer obtains its own nonce and constructs the fixed `opensea.io` login message. Callers cannot supply a message, domain, destination, chain, signature or arbitrary scope. It requests only `read:eligibility`. Signing is off-chain; it creates no mint task, spending reservation or blockchain nonce. Private keys never go to OpenSea.

Login cookies, the scoped token and wallet JWT remain inside the signer boundary. Credential state is encrypted with AES-256-GCM using a purpose-separated key derived from the protected vault secret. Associated data binds the ciphertext to the consent's user, wallet, address, revision and expiry. The API database holds consent metadata only. The signer independently pins that consent. Its public responses whitelist stage fields and never return credentials or login signatures.

JWT renewal uses the scoped token while it remains valid. A known token expiry can reauthenticate only within the still-active, independently pinned consent and a valid imported-wallet approval. An unexpected authentication rejection blocks further use until a new explicit consent. Expired permission, disabled account, wallet unlink or revoked signing approval blocks lookup. Disconnect/unlink disables access locally immediately and attempts remote token revocation; failed cleanup remains encrypted for retry. Already issued upstream JWTs can remain valid until their upstream expiry, but Mintly does not expose or use them after local revocation.

Mint plans offer **Choose mint phase**. The screen displays project-provided labels, eligibility, price, WAT timing and verified remaining allowance. The published default allocation is displayed separately. Remaining allowance is the authenticated running wallet cap minus the receiving wallet's lifetime mint count, constrained by remaining supply; unknown values stay unverified. No receiving wallet inherits a followed wallet's whitelist rights.

Selecting a phase and quantity saves the phase's UUID, type, timing, price and allocation fingerprint. This does not authorize spending. Refresh cannot silently select another phase. Changed phase metadata needs another review. Existing in-flight or unresolved signed mints block phase changes. The ordinary mint review still requires wallet approval, WAT time, gas/total limits and explicit mint consent. Wallet-specific proofs and exact calldata are verified before arming and again by the signer.

OpenSea's mint builder chooses its first eligible active stage, so a valid eligibility response is not sufficient to execute any selected phase. If the builder returns a different phase, Mintly refuses it. Identical overlapping whitelist windows that cannot be distinguished reliably are unavailable for automatic arming. Upcoming proofs that the project has not released remain unverified. GTD is the project's label, not a guarantee of successful inclusion.

This release changes no Android native interfaces or dependencies and can reach 1.1.2+5 and the four previous installers through audited OTA. No existing wallet is opted in during migration. Existing mint/copy approvals and history are retained. Real-wallet authentication was not invoked during agent testing; the wallet owner must accept consent in the app before the first live lookup.

Protocol references: [OpenSea authentication](https://docs.opensea.io/reference/auth), [eligibility](https://docs.opensea.io/reference/get_drop_eligibility), [mint builder](https://docs.opensea.io/reference/build_drop_mint_transaction), and the public [SDK](https://github.com/ProjectOpenSea/opensea-sdk) authentication wire format and `@opensea/api-types` stage schema.
