# OpenSea key storage, pacing and instruction reuse

The root API and discovery worker own the existing persistent OpenSea key cache under the protected shared deployment directory. The signer and copy worker mount only that API-key directory read-only; no wallet key, keystore password or private signing journal is exposed to the API or discovery/copy workers. The shared directory is mode 0750 with service group 10001; the key is atomically replaced at mode 0640 with that group. Read-only clients never request a new key if the cache is missing or expired: they defer while the owner renews it. Owner renewal is serialized with a shared-volume file lock. The API checks for renewal every five minutes, starting one hour before expiry, only on the explicitly configured production deployment. A still-valid key is reused during ordinary requests.

`opensea_request_gates` persists pacing and provider cooldowns across processes and deployments. All metered API requests share a conservative global permit; mint preparation and key creation have additional group spacing. Authenticated eligibility reads share the same permits without sending credentials to the coordinator. Numeric or HTTP-date Retry-After values are honoured. An exhausted reported account bucket also blocks until its reset. A nonempty account bucket's reset is not substituted for a narrower endpoint's Retry-After. Cooldown rejection happens before making an external request and is logged as a local deferral with no invented upstream HTTP code.

Public schedules have a small, bounded 15-second process cache. Unsigned mint instructions enter the bounded 60-second process cache only after contract, receiving address, quantity and proof validation. The signer also caches verified instructions encrypted in its private durable journal for at most five minutes and never beyond the approval expiry. A purpose-separated AES-GCM key and associated data bind the encrypted entry to task ID, exact authorization/policy intent and cache expiry. Entries cannot be substituted between wallets, chains, phases, quantities or budgets. A corrupt or mismatched entry is a cache miss. On reuse, the signer still verifies phase parameters, on-chain proof/signature, allowance, supply, fees, account identity, balance and authorized spending limits before allocating/signing a nonce. No public phase fallback is enabled.

Temporary preparation failures now back off within the existing approved submission window, including after six transient failures. Provider Retry-After and shared-pacing hints set the earliest retry time. Backoff grows up to five minutes when no longer wait is supplied. A cooldown beyond the approval's deadline wakes the task at the original deadline to expire and release its reservation without signing. Permanent validation/policy failures remain terminal. Cancellation and wallet unlink remain effective. Already-failed, disarmed or expired tasks are not revived, and signed-byte/nonce recovery rules are unchanged.

Tests use disposable credentials and the isolated EVM; deployment verification reads configuration, permissions, mounts, key-cache equality, schema and existing task states. No customer mint is armed, retried or submitted as a test. Existing authorizations are not rewritten. This is a backend-only change and requires no mobile OTA.

Free-tier quotas and provider limits still apply. Pacing reduces avoidable quota exhaustion; it cannot guarantee access or mint inclusion, and increasing permitted throughput requires an appropriate OpenSea key/plan rather than creating more instant keys.
