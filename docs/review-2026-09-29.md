# Deployment review — 29 September 2026

## Decision

The backend can be hosted as an authenticated demo service. **Live automatic
minting is not ready.** Earlier README/handoff assertions of complete financial,
concurrency, eligibility, and SSRF guarantees were not supported by the code.
This is a deployment-focused review, not a complete security certification.

## Confirmed blockers corrected

1. **CI import failure:** run 36613286670 failed before collecting tests because
   SQLAlchemy async support lacked `greenlet`. Direct dependencies are now pinned,
   including `SQLAlchemy[asyncio]`. CI and the image both use Python 3.12.
2. **Broken first deploy:** scripts copied a nonexistent `backend/.env.example`,
   assumed Docker existed, ignored application secrets in Compose, and stopped
   the whole stack before rebuilding. Deployment now provisions Docker when needed,
   creates protected shared configuration, builds before recreation, runs Alembic,
   and waits for health checks.
3. **Unauthenticated production:** DEBUG defaulted to true and bypassed owner
   authorization; several read and mutation endpoints were unprotected. All `/api`
   routes now require the owner token in production, startup rejects unsafe production
   settings, and wildcard credentialed CORS was removed.
4. **False transaction success:** any 66-character hash was treated as a simulated
   confirmation. Simulation now requires the task's explicit demo flag. Real hashes
   go through receipt lookup. `ALLOW_LIVE_BROADCAST` now exists and is enforced before RPC.
5. **Misleading deployment results:** absent SSH credentials returned exit 0, the
   server pulled a moving branch, and there were no deployment health checks.
   CI now fails on missing credentials, uploads the tested revision, verifies SSH
   host keys, serializes deployment, and checks local and public health.
6. **Mobile connection:** release Android builds lacked INTERNET permission, the URL
   was hardcoded to an emulator, and request failures could become demo success.
   The app now supports an HTTPS server connection with an in-memory owner token;
   connected failures propagate to the UI. Offline imports no longer claim success.

## Remaining findings, ranked by severity

### P1 — Worker claims are not atomic; recovery and nonce handling are incomplete

`backend/app/worker.py:30` selects a ready row, then assigns a lease and commits.
There is no row lock or conditional update. Two independent sessions can select
before either commits. The existing test makes sequential calls on the same session,
so it does not establish concurrent safety. The worker also defaults the nonce to
zero (`worker.py:112`), always builds public-mint calldata (`worker.py:103`), and
reconciles only `submitted` tasks. Crashes leaving `preparing` or `submitting` tasks
can strand them. Disarm uses a read-then-write update and does not exclude `preparing`.

Before live use: implement PostgreSQL row locking/CAS, real concurrent-session tests,
nonce coordination, atomic disarm, and recovery tests at each persisted transaction
boundary, including finality and reorg handling. Only one demo worker is deployed.

### P1 — Authorization does not fully bind stage, wallet, and execution

`backend/app/api/tasks.py:111` loads a stage by ID without checking that it belongs
to the requested drop. The arm route does not repeat draft quantity checks and
silently falls back to a default wallet for an unknown wallet ID. Repeated idempotency
keys are not handled as repeat requests. At `backend/app/services/signer/base.py:112`,
only public-mint calldata is decoded even though an allowlist selector is permitted.
Stage name, expiry, and revoked authorization are not fully enforced at signing.

Before live use: reject mismatched entities, enforce all limits at arm and sign time,
reject unsupported selectors, and make idempotency deterministic. Do not add a real
signer key to this deployment.

### P1 — Eligibility currently overstates evidence

`backend/app/services/opensea_client.py:125` reports public stages as eligible based
on their name. It does not query the wallet balance, current sale window, remaining
supply, or per-wallet mint count. The OpenSea endpoint/schema has not been verified
against a real collection. UI rechecks and several preferences remain local placeholders.

Before live use: return unknown until evidence is obtained from verified APIs/contracts,
record wallet and freshness, and invalidate evidence when inputs change.

### P2 — URL fetcher does not fully enforce its advertised SSRF/size boundary

`backend/app/services/url_validator.py:76` uses a buffered GET after a separate DNS
validation. The body is downloaded before the size check, and the transport resolves
DNS again, leaving a rebinding window. Authentication limits who can invoke imports,
but it does not repair this fetcher. Use a resolver/transport that connects to the
validated address and stream the response with a byte limit.

### P2 — Discovery and notification integration remain unverified

No X session or push credentials were supplied. Discovery polling does not demonstrate
a complete persisted ingestion path. No authenticated upstream X read, device push,
or on-chain execution was performed. Offline demo amounts still use floating point
in parts of the UI; they must not become authorization amounts.

## Evidence and readiness

- Backend: 22 tests pass locally and in the deployed Python 3.12 Linux image.
- Mobile: Flutter analysis reports no issues; all 8 tests pass, including authenticated
  API error handling and offline demo isolation.
- PostgreSQL: clean Alembic migration succeeds; `alembic check` reports no schema drift.
- Deployment: HTTPS health responds; anonymous `/api/wallets` returns 401; API and
  PostgreSQL containers are healthy; worker is running.
- Demo: offline UI and authenticated server available; full scheduled execution
  remains subject to the limitations above and is not certified.
- Discovery/notifications: not ready without credentials and end-to-end evidence.
- Eligibility: not ready for live decisions.
- Live automatic minting: blocked; production Compose forces demo mode and disables broadcast.

No real wallet key was installed, no real transaction was broadcast, and no push
notification was sent to an external user.
